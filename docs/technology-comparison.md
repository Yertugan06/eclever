# Technology decisions for the first EClever release

**Legal deployment constraint:** [Kazakhstan Law 94-V, Article 12(2)](https://old.adilet.zan.kz/rus/docs/Z1300000094) requires personal-data storage in-country; Article 16 governs cross-border transfer. The external LLM path needs a deployment-specific legal review.

**Decision basis:** [requirements](requirements-specification.md), particularly FR-EXR, FR-KNW, FR-TUT, NFR-SEC-03, NFR-PRV-01/03, NFR-PRF-01/02 and NFR-MNT-01. All choices are design commitments pending implementation and measurement. Current provider terms and prices must be rechecked before production use.

| Decision | Alternatives compared against requirements | Choice, accepted cost, revisit condition |
|---|---|---|
| **D1 Server platform** | [FastAPI](https://fastapi.tiangolo.com/features/) is Python-native with Pydantic and OpenAPI; [Django + DRF](https://www.django-rest-framework.org/) provides an admin and mature ORM but separates API code from the planned Python modelling less cleanly; [NestJS](https://docs.nestjs.com/) provides TypeScript and OpenAPI but adds a second backend language beside BKT/evaluation. | **FastAPI.** One language for API and estimator, documented REST contract, and team experience. We accept building a small Administrator CLI instead of a built-in admin. Revisit if auth/admin work outweighs that benefit. |
| **D2 Data storage** | [PostgreSQL](https://www.postgresql.org/docs/current/datatype-json.html) gives relations, transactions and JSONB; [MySQL](https://dev.mysql.com/doc/refman/8.4/en/json.html) gives relations and JSON but different JSON indexing/queries; [MongoDB](https://www.mongodb.com/docs/manual/core/transactions/) handles flexible documents but would move Class/Skill integrity into application code. PostgreSQL plus MongoDB adds two stores and deletion paths. | **PostgreSQL alone**, one schema per module. Skill dependencies, rosters and atomic Submit updates favour relations; JSONB holds varied event payloads at pilot scale. Accept one database as a scaling unit. Revisit after measured event volume. |
| **D3 Component interaction** | REST/JSON with in-process module calls and direct runner HTTP keeps one request/result path; a [durable queue](https://www.postgresql.org/docs/current/sql-select.html#SQL-FOR-UPDATE-SHARE) with workers and polling preserves overload work but adds state; WebSocket/SSE push adds connection complexity and does not increase sandbox slots. | **REST/OpenAPI**, in-process interfaces, direct synchronous runner HTTP with a bounded in-memory FIFO wait line. Hints are returned only after full validation. Accept lost waiting requests on runner restart; no Submission is recorded before a result. Revisit if 30-burst latency fails or demand exceeds roughly 150 simultaneous Students. |
| **D4 Code execution** | [Docker](https://docs.docker.com/engine/security/) shares the host kernel; [gVisor](https://gvisor.dev/docs/) intercepts sandbox syscalls with a user-space kernel; [Judge0](https://github.com/judge0/judge0) offers a ready API but a larger service and licence footprint; [Pyodide](https://pyodide.org/en/stable/) runs in the browser but client results cannot be trusted for mastery evidence. | **Own runner with Docker + gVisor**, one-use warm sandboxes, no network, read-only root and resource limits (NFR-SEC-03). Accept operational work and benchmark warm starts; development-only plain Docker is not security evidence. Revisit if the Kazakhstan host cannot run `runsc`, then assess `nsjail` and document weaker isolation. |
| **D5 LLM provider** | [OpenAI's under-18 guidance](https://developers.openai.com/api/docs/guides/safety-checks/under-18-api-guidance) requires child safeguards and zero data retention before processing under-13 personal data; [Gemini API terms](https://ai.google.dev/gemini-api/terms) prohibit an app likely accessed by under-18s. A self-hosted open model could keep inference in-country but adds GPU operations and unproven Russian hint quality. | **OpenAI through a provider adapter**, using available project credits and [moderation](https://developers.openai.com/api/docs/guides/moderation). Pin a model ID after Russian Hint safety and quality checks, accounting for the provider’s under-18 recommendation to use strong current safety protections. Scrub identifiers and fail closed; request zero data retention and confirm the legal basis before real children use it. Accept external service dependence and an unresolved cross-border risk. Revisit if scrubbing or provider terms prevent safe use. |
| **D6 Knowledge estimation** | An own four-parameter BKT can update online transparently; [pyBKT](https://github.com/CAHLR/pyBKT) provides fitted variants and validation offline but adds a compiled dependency online; [pyKT](https://github.com/pykt-team/pykt-toolkit) supports deep models but needs substantially more data/compute. A simple rolling rule gives a baseline. | **Rule-based live baseline and own BKT behind one interface; pyBKT offline** for fitting and probability equivalence. Accept simpler BKT assumptions and test them in EX-1/EX-2. Revisit if observed data support richer variants. |

**Other selected tools:** React + TypeScript for the web client ([React](https://react.dev/), [TypeScript](https://www.typescriptlang.org/docs/)) and Monaco for typed-Python editing ([Monaco](https://microsoft.github.io/monaco-editor/)). These are secondary choices, and the prototype is static HTML. No hosting provider or legal conclusion has been selected. The [architecture ADR](adr/0001-modular-monolith-schema-per-module.md) compares the overall modular monolith with a shared-table monolith and microservices.
